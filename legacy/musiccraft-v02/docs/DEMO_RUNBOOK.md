# 课堂演示：3–5 分钟

## 本周没有 GPU 时的讲法

开场明确说：「这次展示产品流程与工具规划，音频使用合成占位；真实模型效果会在下一阶段验证。」当前可展示上传、方案确认、任务状态、试听、版本与回放。不要把占位音频的变化解释为模型完成了风格或音色转换。

## 正式演示前准备

- 运行 `python3 -B run.py`，检查顶栏模式和模型连接状态。
- 准备一段 10–20 秒源歌曲、组员本人 10–20 秒干净录音。
- 真实模式下预先跑好：原曲 → 风格 A、原曲 → 风格 B、原曲 → 组员声音，逐一听测后收藏到演示台。
- 录下每项的输入、目标、参数、模型 revision、端到端耗时、成功与失败情况；用导出记录保存任务快照。
- 收藏仅保存在这份项目的 `data/`。打包源码不包含私人录音、数据库、真实样例。更换演示电脑时单独复制经授权的 `data/`，完整保留来源标记。
- 不在展示前更新模型或依赖。演示台回放不需要 GPU，不发起新推理。

## 推荐顺序

### 0:00–0:30 · 问题与范围

「我们希望用户用文字编辑歌曲，不必自己组合音乐生成、源分离和音色转换工具。第一期只聚焦整体风格改编和参考音色翻唱；从零作曲暂缓。」

### 0:30–1:30 · 同一首歌，不同风格

1. 打开风格改编，展示原曲、片段起点与目标要求。
2. 解析方案，说明结构化参数、旋律保留软约束、用户确认执行。
3. 若已预热且时间充裕，现场提交；同时打开演示台的历史真实结果先试听。
4. 对比原曲和两个风格，指出成功之处与不足。历史结果明确称为预生成结果。

### 1:30–2:45 · 换成组员的声音

1. 展示原曲和目标声音参考，说明参考录音无需训练。
2. 打开已完成的真实翻唱结果，依次播放原唱分轨、转换后歌声、最终混音。
3. 指出三步管线：Demucs 分离 → Seed-VC 转换 → FFmpeg 混音；伴奏来自分离轨。
4. 解释音色相似度和分离伪影的实际限制，不宣称完美克隆。

### 2:45–3:30 · Agent 的贡献

展示任务参数、执行事件、父版本。说明 LLM 提取本轮要求，后端验证素材与约束、选择工具、保存结果；音频模型负责声音本身。若顶栏是 rules，应明确当前演示用离线规则，LLM 是已提供的可接入模块。

### 3:30–4:30 · 研究计划与评估

问题：「结构化约束与工具路由能否改善连续编辑中的内容保留？」对比直接提示与结构化规划，固定音频模型、种子和生成预算。人工盲听评估风格、旋律、音色、音质，同时记录耗时、失败率。展示一个失败例更能说明评估标准。

## 现场故障处理

- GPU 排队或超时：明确说实时任务仍在等待，切换演示台的历史真实结果；不把回放说成新生成。
- 服务断连：不反复点击生成；先查看日志和远端任务状态。
- 只剩 DEMO：继续展示交互和架构，明确音频为占位。
- 方案阻止：解释缺少音频、保留伴奏与整体重生成冲突，修正后重新解析。

## 一个月内的最低完成标准

两项真实管线各至少 3 个可复现样例；至少一个原曲到两个风格的对照；一个组员音色转换成功例；真实结果可回放；失败状态可解释。课程研究部分需实际启用 LLM 规划并与对照组评估，不能只用规则演示声称已完成 LLM 研究。
